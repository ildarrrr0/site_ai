# idmAI — лендинг с живым демо-ботом

Лендинг личного бренда **idmAI**: демонстрация ИИ-Менеджера для салонов красоты и косметологии. Внутри — реальный работающий чат-бот на GigaChat (Алина, тот же системный промпт и та же живая база знаний, что и в продакшен-боте `salon_ai_bot`), а не имитация с прописанными ответами.

## Структура репозитория

```
index.html        — весь лендинг (один файл, стили и скрипты инлайн) — грузится на GitHub Pages
api/chat.js        — serverless-функция для Vercel: держит GigaChat-токен, собирает системный промпт + базу знаний
api/prompt.js      — системный промпт Алины (по умолчанию — как в alina_guide.md; можно переопределить переменной окружения)
api/knowledge.js   — загрузка живой базы знаний (услуги, цены, мастера) из тех же Google-таблиц, что и в salon_ai_bot
package.json       — метаданные проекта для Vercel
```

## Архитектура бота

Лендинг лежит на GitHub Pages — это статический хостинг, весь код там виден любому через «просмотр кода страницы». Поэтому GigaChat-токен физически не может лежать в `index.html`.

Разделение такое:

1. **`index.html` (GitHub Pages)** — только `fetch()` к бэкенду. Токена в этом файле нет вообще.
2. **`api/chat.js` (Vercel Functions)** — принимает сообщение с сайта, подтягивает живую базу знаний (`api/knowledge.js`, те же публичные Google-таблицы, что в `salon_ai_bot/config.py`) и дёргает GigaChat (та же логика, что в `salon_ai_bot/gigachat_client.py`: OAuth по `GIGACHAT_AUTH_KEY`, кэширование `access_token`, запрос к `chat/completions`), возвращает ответ. Токен и системный промпт хранятся только в переменных окружения на Vercel.

Демо-бот на лендинге — это тот же ИИ-Менеджер Алина, что работает в реальном Telegram-боте: тот же системный промпт и та же (реальная, актуальная) база услуг/цен/мастеров.

Так секрет физически не может утечь через статическую страницу.

## Как задеплоить бэкенд (Vercel) — 10 минут

1. Зайдите на **[vercel.com](https://vercel.com)** и войдите через GitHub-аккаунт (тот, где лежит `ildarrrr0/site_ai`).
2. **Add New… → Project → Import Git Repository** → выберите `ildarrrr0/site_ai`.
3. Framework Preset можно оставить `Other` — ничего собирать не нужно, Vercel сам подхватит папку `api/` как serverless-функции. Нажмите **Deploy**.
4. Первый деплой пройдёт успешно, но бот пока не ответит — не заданы переменные окружения. Идём в **Project → Settings → Environment Variables** и добавляем:

   | Переменная | Значение | Обязательна |
   |---|---|---|
   | `GIGACHAT_AUTH_KEY` | Authorization key из личного кабинета GigaChat API (developers.sber.ru → GigaChat API → ваш проект → «Ключ авторизации», строка в Base64) | да |
   | `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` (или `GIGACHAT_API_B2B` / `GIGACHAT_API_CORP` — в зависимости от вашего тарифа) | нет, по умолчанию `GIGACHAT_API_PERS` |
   | `ALLOWED_ORIGIN` | `https://ildarrrr0.github.io` — домен вашего GitHub Pages, чтобы бэкенд отвечал только вашему сайту | нет, но рекомендуется |
   | `GIGACHAT_SYSTEM_PROMPT` | Свой текст системного промпта, если хотите заменить встроенный демо-сценарий под конкретный салон | нет, есть встроенный по умолчанию |

   Важно: значения переменных окружения нигде не попадают в код и не видны в браузере — это и есть то самое безопасное хранение токена.

5. После добавления переменных: **Deployments → последний деплой → ⋯ → Redeploy** (чтобы функция подхватила новые переменные).
6. Скопируйте адрес вашего проекта — он вида `https://site-ai-xxxx.vercel.app`. Полный адрес функции: `https://site-ai-xxxx.vercel.app/api/chat`.
7. Откройте `index.html` в репозитории, найдите строку

   ```js
   const API_ENDPOINT = 'https://YOUR-VERCEL-PROJECT.vercel.app/api/chat';
   ```

   и замените на ваш реальный адрес из шага 6. Закоммитьте и запушьте изменение.

Готово — демо-чат на лендинге теперь дёргает настоящий бэкенд с настоящим GigaChat.

## Как включить GitHub Pages

1. В репозитории: **Settings → Pages**.
2. Source: **Deploy from a branch**, ветка — та, где лежит актуальный `index.html` (после мёржа обычно `main`), папка — `/ (root)`.
3. Сохраните — через минуту сайт будет доступен по адресу `https://ildarrrr0.github.io/site_ai/`.

## Встроенная защита бэкенда

`api/chat.js` уже включает базовую защиту от злоупотреблений: лимит запросов на IP (20 запросов в минуту), ограничение длины истории и сообщений, CORS только для разрешённого источника (`ALLOWED_ORIGIN`). Для демо-лендинга этого достаточно; при росте нагрузки стоит рассмотреть постоянное хранилище для rate-limit (например, Vercel KV) вместо памяти процесса.
